## L1 — Missing index prints FREEZE sigma-hat. Is that where F-M06 and F-M08 come from?

**F-I05** (a collector restart inside a UTC hour leaves two gzip members and the
reader recovers ZERO lines, not half) x **F-M06** (multiplying the volatility
estimate by 1.25 makes the bad rate WORSE, 2.90% -> 3.09%; at 2.0x, 4.62% —
distrusting the model more does not help).

`engine.py:121` updates the volatility EWMA only when `sec - prev == 1`. A gap
in the index does not inflate sigma-hat and does not decay it — it **freezes**
it, and `sigma_rel_se` keeps reporting a full sample's standard error because
`self.n` stops growing too. A frozen estimate carried from a calm stretch into a
live one is a wrong-regime error, not a scale error — the one shape a uniform
multiplier cannot fix (F-M06), and the shape that would make the
lowest-measured-volatility fifth the worst (F-M08, 43.7x overconfident).

**Measure:** per candidate decision time, the AGE of sigma-hat (seconds since
the last consecutive-second update), and sigma-hat over the volatility actually
realised in the window it forecasts. Then re-run the F-M06 multiplier test and
the F-M08 quintile split with the stale tail excluded, and report what survives.

**Artefact if:** a shorter effective sample mechanically lowers an EWMA's

**MDE, first.** Powered version is continuous: ratio against sigma age. 16,683
candidates at the measured 31-46x design effect (F-R02) is ~440 independent
closes, MDE ~0.13 of the ratio's own spread — enough for a 15% staleness bias.
The RATE version is dead on power: 2.90% -> 5.8% needs ~780 closes per arm
against ~440 in total, so a null there is no power, not no effect. Census
coverage first; if gap-adjacent candidates are only a few per cent, stop.

**Not a loss rate.** Every number here is the model's error against the index on
