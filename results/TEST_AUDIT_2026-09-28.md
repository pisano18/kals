### Notes (incl. why bars.py was wrong)

WHY bars.py IS WRONG (three measured causes):
(1) THE MAIN ONE: live log results/pinrun-live-20260925T122357Z.jsonl lost its front on disk. It now starts 09-26 07:31:21Z with no start record. bars.live_runs() skips any log without a start record, so the live bot looks switched off from 09-25 8:23 AM ET to 09-27 1:08 AM ET (42 h). That window holds the BTC -$131.98 loss. Every arm-vs-live read and the fresh-offer bar have been wrong since. This, not the name mapping, is why arm-live-frozen showed 1 market (32 now, 113 once repaired). The two halves exist: git HEAD holds 09-25 12:23Z to 09-26 07:30Z (60 settled records), and the working file holds 09-26 07:31Z to 09-27 05:08Z. I rebuilt both in scratch and wrote nothing under results/.
Fix: restore the file as HEAD content plus the current file. That writes a tracked log, so it needs the session's OK; the bot finished with it 09-27. Also make live_runs WARN loudly and use the first record's time instead of silently dropping a log with no start record.
(2) pinrun's start record does not carry --toxic-fresh, --fresh-min-age-ms/--fresh-tau-min, --rebuy-late-tau/--rebuy-late-frac or --one-full-bet, and newer runs have no arm_name. So arm_groups() puts arm-fresh500, arm-toxic, arm-btcd and arm-lateadd-off in ONE group together with every live-identical log since 09-20 (33 logs). bars prints identical numbers for all four (+$82.78) and reads the btcd and fresh arms from that mixed group.
Fix: in pinrun.py, put the full argv and arm_name into the start record. In bars, map a log by its arm-*.out name first, then by launch order within a sync batch (sync_arms launches in table order: early-off, brake3, lateadd-off, edge2c, btcd, fresh500, toxic, hourly-all; I verified this against the start-record differences for the 09-25 02:27Z, 09:38Z and 12:25Z batches). Use the signature only as a last resort.
(3) The arm-*.out files name only the current run, so earlier runs of an arm are unnamed.
